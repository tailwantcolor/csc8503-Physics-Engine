# 06 设计讨论手册：模板、流程与评分表

> 一句话：好的设计讨论不是「谁的想法更好」，而是「在什么约束下、为了什么体验、选择哪个方案、如何验证」。

## 0. 使用说明

这份手册是知识库的「操作层」：前面几份文件解释概念，这里把它们变成讨论时可以填写的表格和可以执行的流程。

- 讨论前：用第 1 节对齐五件事；
- 讨论中：用第 2–7 节的模板记录，不要只靠口头；
- 讨论后：用第 7 节的决策记录收尾，下一次从记录继续。

**原则**：先问题、后方案；先约束、后创意；先验证、后承诺。

## 1. 讨论前先对齐的五件事

1. **体验目标**：玩家在关键段落应该感到什么？（2–3 个形容词）
2. **设计支柱**：3–4 条「我们坚持 / 我们不做什么」，每条都能判断对错。
3. **目标玩家与情境**：谁、在什么设备/时长/心境下玩？
4. **约束**：时间、人力、预算、技术、平台、内容分级、商业模式。
5. **本次要做的决定**：这次讨论结束时必须定下什么？谁有权定？

如果五件事里有三件没对齐，先别讨论方案——那会变成各说各话。

## 2. 模板 A：体验目标与设计支柱

```
体验目标（2–3 个词）：
  1.
  2.
  3.

设计支柱（3–4 条）：
  支柱 1：
    - 我们坚持：
    - 我们不做：
    - 判断标准（什么情况算违背）：
  支柱 2：
    ...
  支柱 3：
    ...

目标玩家：
平台/时长：
本次决策：
```

**支柱测试**：给一条具体提案，问「它强化还是违背支柱？」如果两条支柱互相冲突，说明支柱还没想清或项目本身有张力，需要明确优先级。

## 3. 模板 B：核心循环一页纸

```
玩家是谁：
核心幻想：
30 秒循环：目标 → 动词 → 系统回应 → 反馈 → 奖励/代价
5 分钟循环：一场遭遇/房间的结构、战术选择、失败成本
1 小时循环：一章/一局的结构、成长、节奏高低点
长线循环：元进度、重玩动机、叙事弧线

核心决策（最多 3 个）：
  1.
  2.
  3.

体验目标（对应第 2 节）：
```

**示例（假设，不是本项目设定）**：

> 玩家是一名在废城中寻找失踪同伴的拾荒者。30 秒循环：发现可攀爬结构 → 攀爬/荡跃 → 到达新平台 → 看到更远的路线 → 决定是否冒险深入。5 分钟循环：进入一栋建筑 → 搜刮资源 → 遭遇敌人 → 选择战斗/潜行/逃跑 → 带资源离开。1 小时循环：解锁一条新路线 → 推进同伴线索 → 获得新工具 → 回到旧区域打开新路径。核心决策：冒险深入还是安全撤退；正面战斗还是潜行；把有限资源用于工具还是治疗。

这个示例只演示「怎么填」，不预设任何项目的具体方向。

## 4. 模板 C：叙事—玩法整合审计表

这是「叙事性与玩法性兼顾」最直接的工具：把主线的每个叙事节拍，翻译成玩家的动作与系统状态。

| 叙事节拍 | 玩家动作 | 机制/系统 | 系统状态变化 | 反馈 | 服务主题？ | 缺口 |
| --- | --- | --- | --- | --- | --- | --- |
| 例：同伴失踪 | 追踪线索、进入禁区 | 探索/追踪 | 任务状态、区域解锁 | 环境线索、对话 | 是（失去与寻找） | 追踪玩法是否只是「跟着图标走」？ |
| 例：发现真相 | 拼合证据、做选择 | 调查/对话 | 关系值、结局分支 | 演出、日志 | 是 | 玩家是否真的推理，而不是被喂答案？ |
| 例：最终对决 | 战斗/放弃 | 战斗/宽恕 | 世界状态 | 结局演出 | 是 | 战斗是否表达主题，还是纯数值？ |

**使用方法**：

1. 先从故事大纲里列出 8–15 个关键节拍；
2. 每个节拍填「玩家动作」——如果填不出，说明这段只是过场；
3. 填「机制/系统」——如果和主线机制无关，说明叙事和玩法两张皮；
4. 填「系统状态变化」——没有状态变化，后果就不可见；
5. 填「服务主题？」——如果大量「否」，主题需要重写或机制需要重做；
6. 最后一列写「缺口」，就是下一轮设计任务。

## 5. 模板 D：创新主张测试

```
一句话创新主张：
  本作让玩家第一次能够 ____________________________________。

它产生的「新决定」：
  1.
  2.

可读性：玩家如何在 5 分钟内理解它？
深度：它能否组合、精通、反复玩？
主题契合：它如何服务体验目标/叙事？
成本：技术/内容/平衡/教学成本？
风险：失败能否回退？最小验证是什么？
差异化：与同类相比，一句话差异是什么？
证据：现有原型/参考作品/试玩数据支持哪一条？
```

**判断标准**：如果「新决定」填不出来，这通常只是新题材/新皮肤；如果「可读性」需要一大段解释，先做教学原型；如果「最小验证」做不出来，说明提案太大，先拆小。

## 6. 模板 E：品质门槛（按阶段）

| 阶段 | 必须达到 | 可以延后 | 不能妥协 |
| --- | --- | --- | --- |
| 原型 | 核心循环成立、可读 | 美术、音频、UI 精度 | 玩法是否成立 |
| 垂直切片 | 一段内容达到最终品质、管线可复制 | 全量内容 | 品质基准、性能底线 |
| Alpha | 功能完整 | 内容细节、平衡 | 所有系统可玩 |
| Beta | 内容完整 | 少量平衡/演出 | 崩溃率、性能、可访问性 |
| 上线 | 平台合规、稳定 | 后续内容 | 稳定性、公平性、合规 |

**用法**：每个阶段开始时填「必须达到」，结束时逐项验收；不要把「不能妥协」的项目拖到下一个阶段。

## 7. 模板 F：决策记录

```
日期：
议题：
背景/约束：
选项：
  A. 优点 / 缺点 / 成本 / 风险
  B. 优点 / 缺点 / 成本 / 风险
  C. ...
证据（原型/试玩/参考/数据）：
决定：
理由（对应体验目标/支柱）：
验证方式与时间点：
负责人：
复核日期：
```

**规则**：没有决策记录的讨论，视为没发生；下次讨论从记录继续，不重新吵一遍。

## 8. 讨论流程

### 15 分钟（快速对齐）

1. 重申本次要做的决定（1 分钟）；
2. 对齐体验目标与约束（3 分钟）；
3. 列 2–3 个选项，各说优缺点（6 分钟）；
4. 做决定，写记录（5 分钟）。

### 30 分钟（方向讨论）

1. 五件事对齐（5 分钟）；
2. 用模板 B 过一遍核心循环（10 分钟）；
3. 用模板 C 抽查 3 个关键叙事节拍（8 分钟）；
4. 用模板 D 评估一个创新提案（5 分钟）；
5. 决策记录（2 分钟）。

### 60 分钟（评审/拆解）

1. 目标与约束（5 分钟）；
2. 参考作品拆解：它解决什么问题、用什么机制、代价是什么（15 分钟）；
3. 当前方案逐项过模板（20 分钟）；
4. 风险与验证计划（10 分钟）；
5. 决策记录与下一步（10 分钟）。

## 9. 评审评分表（1–5 分）

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 体验目标清晰度 | 只有「好玩」 | 有 2–3 个词但不可检验 | 每个词都能对应机制与验证方式 |
| 循环完整性 | 只有宏循环 | 微/中循环成立，长线模糊 | 三个尺度都成立，且有弧线 |
| 决策质量 | 没有真正的取舍 | 有取舍但可被主导策略破解 | 多个互相制衡的决策，有深度 |
| 叙事整合 | 故事与玩法两张皮 | 关键节拍有玩法支撑 | 机制本身在表达主题 |
| 创新性 | 换皮 | 有一个新点但可读性存疑 | 新决定 + 可读 + 可扩展 |
| 可读性/教学 | 需要大量解释 | 有引导但仍有误读 | 一看就懂、一玩就会 |
| 生产可行性 | 明显超范围 | 有风险但可拆解 | 有垂直切片路径与止损条件 |

**用法**：评分不是目的，低分项才是下一轮任务；同一方案两次评审分数应可比较，便于追踪。

## 10. 常见陷阱

- **只谈感觉，不谈目标**：说了半天「爽」，但说不清爽在哪里、为谁爽。
- **用参考作品代替论证**：「某某游戏也这样」不是理由，要拆解它为什么成立、代价是什么。
- **把创新当目标**：为不同而不同，忽略可读性与成本。
- **过早定方案**：还没对齐体验目标就开始争美术风格。
- **范围漂移**：讨论从「核心循环」漂到「UI 颜色」。
- **没有决策记录**：下次重新吵一遍。
- **忽略失败成本**：只设计成功路径，不设计卡关/误读/放弃点。
- **用指标替代判断**：留存高不等于体验好，时长长不等于有意义。

## 11. 如何用这份知识库讨论

可以直接这样提问（示例）：

- 「按 `03-gameplay-loops.md` 的核心循环模板，帮我把这个玩法拆成 30 秒/5 分钟/1 小时三层。」
- 「用 `06` 的叙事—玩法整合审计表，逐条检查主线节拍，标出没有玩家动作的段落。」
- 「用 `05` 的创新评估表给这三个提案打分，并说明低分项怎么补。」
- 「用 `04` 的体验目标→机制映射表，检查这个关卡的手段是否服务目标情绪。」
- 「用 `02` 的 ludonarrative 四种关系，判断这个故事的机制是否和主题冲突。」
- 「用 `01` 的结构模型比较这三个主线方案，分别指出节奏风险。」

**追问原则**：先问「体验目标是什么」，再问「玩家做什么决定」，最后问「怎么验证」。任何方案都应该能回答这三层。

## 12. 讨论检查清单（会前/会后）

**会前**

- [ ] 本次要做的决定是什么？
- [ ] 体验目标、支柱、约束是否已对齐？
- [ ] 需要哪些参考作品/原型/数据？

**会中**

- [ ] 是否先问题后方案？
- [ ] 是否至少比较了 2 个选项？
- [ ] 是否记录了反对意见与风险？
- [ ] 是否区分了「事实/参考/判断」？

**会后**

- [ ] 决策记录是否完整（选项、证据、决定、验证、负责人）？
- [ ] 下一步的最小验证是什么？
- [ ] 需要更新知识库的哪一条？
