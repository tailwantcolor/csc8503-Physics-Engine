# 04 体验设计：玩家应该感觉到什么

> 一句话：体验设计不是「加特效」，而是从玩家应该感受到的情绪倒推机制、反馈、节奏与难度。

## 1. 体验优先

Jesse Schell 在《The Art of Game Design》中反复强调：游戏是**被体验**的，设计要从「玩家会经历什么」出发，而不是从「我想做什么系统」出发。

**体验目标（experience goal）**：用 2–3 个形容词描述玩家在关键段落应该感受到什么。它不是「好玩」，而是更具体的情绪与状态：

- 紧张、压迫、敬畏、好奇、掌控、陪伴、孤独、荒诞、释然、悲伤、胜利、羞耻、温暖、恐惧、惊奇。

体验目标必须**可被检验**：如果玩家没感到它，哪里出了问题？如果玩家感到了但代价太大（比如为了紧张而让玩家烦躁），是否值得？

## 2. 体验目标 → 机制的映射

| 体验目标 | 常用手段 | 风险 |
| --- | --- | --- |
| 紧张 | 资源稀缺、时间压力、不可逆选择、敌人前摇 | 变成焦虑/挫败 |
| 掌控/精通 | 清晰反馈、可练习的连招、成长可见 | 变成重复劳动 |
| 好奇/发现 | 信息分层、远景地标、未知区域、环境线索 | 变成迷路/无所适从 |
| 敬畏 | 尺度对比、缓慢镜头、音乐留白、自然奇观 | 变成被动观光 |
| 陪伴/亲密 | 同伴 AI、对话、共同经历、关系状态 | 同伴变成工具人 |
| 孤独/压迫 | 空旷空间、资源匮乏、声音设计、无安全感 | 变成无聊/烦躁 |
| 释然/治愈 | 安全区、柔和节奏、可预测的规则、告别 | 变成没有张力 |
| 荒诞/幽默 | 反差、系统失控、物理喜剧、文字游戏 | 破坏严肃主题 |

**用法**：先写体验目标，再从表里选手段，最后问「这些手段会不会同时带来副作用？如何用其他系统抵消？」

## 3. Flow：挑战与技能的平衡

Csikszentmihalyi 的「心流」描述了高度投入的状态，常见条件包括：

- 目标清晰；
- 反馈即时；
- 挑战与技能匹配；
- 注意力高度集中；
- 有控制感；
- 自我意识消失、时间感扭曲；
- 活动本身即奖励（自为目的）。

**游戏中的应用**：

- **清晰目标**：玩家随时知道「现在该做什么」；
- **即时反馈**：每个动作都有可感知的结果；
- **动态难度**：根据玩家表现调整挑战（Jenova Chen 的 *Flow in Games* 讨论了动态难度与心流区间）；
- **减少干扰**：UI、镜头、音效不要和当前任务争夺注意力。

**Flow 的局限**：心流不等于意义。一个刷子游戏也可以让人进入心流，但玩家结束后可能觉得空虚。Flow 是「投入」的条件，不是「值得」的证明。

## 4. 动机：自主、胜任、归属

自我决定理论（Self-Determination Theory, SDT）认为，内在动机依赖三种基本心理需求：

- **自主（autonomy）**：我的选择是我做的，而不是被逼的；
- **胜任（competence）**：我能感到自己变强、变熟练；
- **归属（relatedness）**：我与他人/角色有连接。

**设计含义**：

- 给玩家**有意义的选择**（build、路线、对话态度），而不是假选项；
- 给玩家**清晰的成长反馈**（新能力、新理解、新路线），而不是只涨数值；
- 给玩家**关系与共同体**（同伴、合作、社区、异步连接）。

**内在 vs 外在奖励**：

- 外在奖励（货币、经验、解锁）有效，但可能挤出内在动机（过度奖励效应，overjustification effect）：当玩家为了奖励而玩，原本的乐趣可能被替代。
- 好的做法：奖励**信息、能力、表达空间**，而不只是数值；让奖励解释「你为什么变强了」。

## 5. Fun 与情感：不止一种「好玩」

- Raph Koster 在《A Theory of Fun for Game Design》中提出：乐趣来自**学习与模式识别**——大脑掌握新规律时的愉悦。游戏是「安全的 learning machine」。
- LeBlanc 的八种美学（见 `03-gameplay-loops.md`）提醒我们：「好玩」有很多种，挑战只是其中之一。
- **负面情绪也可以是目标**：恐怖游戏的恐惧、悲剧的悲伤、生存游戏的焦虑、*Spec Ops* 的不适。关键不是「消灭负面情绪」，而是让它们**服务主题**，并且玩家能理解「这是我选择的体验」。
- **情感节奏**：高强度情绪之后需要释放；持续悲伤会麻木，持续欢乐会疲劳。用安静、幽默、日常来对比，让重情绪更有重量。

## 6. 不确定性与张力

Greg Costikyan 在《Uncertainty in Games》中区分了多种不确定性来源：表演性（我能不能做到）、玩家间（对手会怎么做）、随机性、隐藏信息、规则复杂度等。

**张力（tension）** 来自「结果重要 + 结果不确定 + 我不能完全控制」。设计手段：

- 资源稀缺与不可逆消耗；
- 时间压力；
- 敌人前摇/威胁预告（telegraph）；
- 风险/回报选择；
- 信息不对称（玩家知道危险，角色不知道，或反之）。

**张力曲线**：紧张—释放—再紧张。没有释放的持续紧张会变成疲劳；没有紧张的持续安全会变成无聊。

## 7. Game feel：手感的三要素

Steve Swink 在《Game Feel》中把「手感」拆成三个部分：

1. **实时控制（real-time control）**：输入到响应的延迟、加速度、惯性、容错；
2. **模拟空间（simulated space）**：碰撞、物理、镜头、空间感知；
3. **润色（polish）**：动画、音效、粒子、屏幕震动、命中停顿、镜头反馈。

**可操作的检查**：

- 输入延迟是否可感知？是否给玩家「预输入缓冲」与「动画取消」的余地？
- 动作是否有「重量」？起手、命中、收招是否清晰？
- 命中是否有层次？轻击/重击/暴击/击杀的反馈是否不同？
- 镜头是否服务动作？是否有过度震动/晃动导致不适？
- 音效是否与动作同步？是否有「听感确认」？
- 「juice」是否服务可读性？特效太多会遮住关键信息。

**手感的常见误区**：

- 把「更多粒子/更多震动」当成手感；
- 只调动画，不调输入与判定；
- 为了「真实」牺牲响应（真实感与可控感经常冲突）；
- 不同动作的反馈没有层级，玩家分不清轻重。

## 8. 反馈与可读性

**反馈的三个时间层**：

- **即时**：按键→动作→命中（毫秒级）；
- **短期**：一场战斗/一个房间的结果（秒—分钟）；
- **长期**：成长、关系、世界变化（小时—周）。

**可读性（readability）**：玩家能否在正确的时间看到正确的信息。

- **视觉层级**：危险 > 目标 > 环境 > 装饰；
- **颜色/形状语言**：可交互物、危险、可攀爬、可破坏要有一致的视觉规则；
- **telegraph**：敌人攻击前要有可识别的预警（动作、颜色、声音）；
- **UI**：HUD 信息要能「扫一眼就懂」；diegetic UI（游戏内界面）可以增强沉浸，但不能牺牲可读性；
- **声音**：方位、距离、材质、危险提示；音频是反馈的一半。

## 9. 难度与公平

- **难度是体验语言**：它表达威胁、节奏、主题。难度曲线不只是数值曲线，也是「学习曲线」。
- **公平**：规则一致、前摇可读、失败可归因、检查点合理。玩家可以接受「难」，但不能接受「被耍」。
- **难度选项**：更多难度/辅助选项不会「毁掉」游戏，反而扩大受众；关键是让选项服务体验，而不是让玩家绕过核心乐趣。
- **动态难度**：可以缓解卡关，但要透明、可预期；暗中大幅调整会破坏「我变强了」的胜任感。
- **失败的成本**：重试时间、跑图距离、资源损失——失败成本越高，玩家越保守，体验越紧张；要按目标情绪调整。

## 10. Onboarding：前十分钟决定很多事

- **教，而不是告诉**：让玩家在安全环境里做一个动作，立刻看到结果，再给下一个动作。
- **一屏一个概念**：不要在同一段里教三个系统。
- **show, don't tell**：用关卡、敌人、道具表达规则；文本只做补充。
- **第一分钟要有「爽点」**：玩家要先感到「我能做一件有趣的事」，才愿意学复杂规则。
- **允许跳过/重看**：尊重熟练玩家与回归玩家。
- **经典案例**：*Super Mario Bros.* 的 1-1 用关卡本身教跳跃、蘑菇、管道、敌人，几乎没有文字。

**新手引导检查**：

- [ ] 玩家在 60 秒内是否做了一个「有意义」的动作？
- [ ] 每个新机制是否在安全环境里先出现？
- [ ] 是否有「练习—反馈—再来一次」的循环？
- [ ] 文本是否只补充「玩家无法从画面推断」的信息？
- [ ] 熟练玩家能否快速跳过？

## 11. 社交体验

- **合作（co-op）**：共同目标、互补角色、沟通需求。强制合作（*It Takes Two*）能创造独特的体验，但也限制受众。
- **对抗（PvP）**：公平、可读、反制空间；匹配与挫败管理。
- **异步社交**：留下痕迹、共享设施、排行榜、UGC；适合不想实时社交的玩家。
- **归属感**：公会、社区、创作者生态；不只是游戏内功能，也是运营与社区设计。

## 12. Playtesting：试玩是真相

- **观察，而不是询问**：玩家说「很好玩」不一定可信；看他们卡在哪、什么时候放下手柄、什么时候笑。
- **沉默测试**：不要在旁边解释；玩家看不懂，就是设计问题。
- **目标玩家**：第一次玩的人、熟练玩家、非目标用户，分别测不同问题。
- **问开放问题**：「你刚才想做什么？」「你为什么选这个？」而不是「你喜欢吗？」
- **小样本多次**：5 个玩家发现的共性问题，比 50 份问卷更有行动价值。
- **记录**：卡点、误读、情绪峰值、放弃点；把观察转成可执行的修改项。

## 13. 可访问性

可访问性不是「额外功能」，而是体验设计的一部分：

- **视觉**：字号、对比度、色盲模式、高对比、镜头晃动/闪光可关闭；
- **听觉**：字幕、方向提示、视觉化音效；
- **操作**：按键重映射、灵敏度、辅助瞄准、长按/切换、单手模式；
- **认知**：难度选项、任务提示、回顾、跳过；
- **运动**：减少镜头运动、避免强制快速反应。

*The Last of Us Part II* 是常被引用的案例：大量可访问性选项覆盖视觉、听觉、操作、认知，且不破坏核心体验。可访问性做得好，往往也会提升所有玩家的体验。

## 14. 体验目标 → 机制映射表（模板）

```
段落/关卡：
体验目标（2–3 个词）：
玩家此刻应该：
  - 看到什么：
  - 听到什么：
  - 做什么决定：
  - 担心什么：
  - 获得什么反馈：
机制/系统如何服务它：
可能的副作用：
如何抵消副作用：
验证方式（试玩观察点）：
```

## 15. 讨论检查清单

- [ ] 这个段落的体验目标是什么？用三个形容词说清。
- [ ] 玩家在 60 秒内做了什么有意义的动作？
- [ ] 挑战与技能是否匹配？卡关时玩家能否自己发现原因？
- [ ] 反馈是否即时、可读、有层级？
- [ ] 手感的三要素（控制、空间、润色）是否都成立？
- [ ] 难度/失败成本是否服务目标情绪？
- [ ] 新手引导是否「教」而不是「告诉」？
- [ ] 是否有释放/安静的时刻？
- [ ] 可访问性选项是否覆盖主要障碍？
- [ ] 试玩中玩家实际做了什么、误读了什么？
