# 03 玩法循环：从 30 秒到一局，玩家在反复做什么

> 一句话：玩法循环是玩家「目标 → 行动 → 系统回应 → 反馈 → 新目标」的重复结构；循环的质量，决定玩家为什么愿意再来一次。

## 1. 循环的三个尺度

| 尺度 | 时长 | 例子 | 设计问题 |
| --- | --- | --- | --- |
| 微循环（micro） | 秒级 | 一次跳跃、一次射击、一次闪避、一次对话检定 | 手感是否可读？反馈是否即时？ |
| 中循环（meso） | 分钟级 | 一场战斗、一个房间、一次探索、一个任务 | 是否有战术选择？节奏是否有起伏？ |
| 宏循环（macro） | 小时/局/周 | 一章、一局 roguelike、一个赛季、一条主线 | 是否有成长？是否有目标感？是否值得重玩？ |

**常见错误**：只设计宏循环（「玩家会玩 40 小时」），却没有设计微循环（「按下去爽不爽」）；或者反过来，手感很好但不知道为什么继续。

## 2. 循环的最小结构

```
目标（我想要什么）
  → 行动（我按了什么/做了什么决定）
    → 系统回应（世界怎么变）
      → 反馈（我如何知道结果）
        → 奖励/代价（我得到/失去什么）
          → 新目标（下一步我想要什么）
```

**技能原子（skill atom）**：Daniel Cook 用「目标—行动—模拟—反馈—建模」描述玩家学习一个机制的过程。玩家每掌握一个技能原子，就获得一个新的「可玩空间」；多个技能原子串成技能链，构成中循环。

**循环与弧线（loops and arcs）**：Cook 区分两种结构：

- **循环（loop）**：可重复、可上瘾的行为（刷、打、收集、对局）。
- **弧线（arc）**：有起点、有推进、有终点的一次性体验（章节、主线、角色关系）。

好游戏通常**用循环维持日常乐趣，用弧线提供意义与终点**。只有循环没有弧线，会变成「打工」；只有弧线没有循环，会变成「一次性体验」。

## 3. MDA：机制、动态、美学

**MDA（Mechanics–Dynamics–Aesthetics）** 由 Hunicke、LeBlanc、Zubek 提出：

- **Mechanics（机制）**：规则、数据、算法——设计师直接写的东西。
- **Dynamics（动态）**：机制在玩家操作下运行时产生的行为——设计师不能直接写，只能通过机制和测试去「引导」。
- **Aesthetics（美学/体验）**：玩家实际感受到的情绪反应——设计的真正目标。

**八种美学**（MDA 论文中的分类，常被引用）：

1. Sensation（感官刺激）
2. Fantasy（幻想/扮演）
3. Narrative（叙事）
4. Challenge（挑战）
5. Fellowship（社交/陪伴）
6. Discovery（发现）
7. Expression（表达）
8. Submission（消遣/沉浸）

**用法**：先选 2–3 个目标美学，再问「哪些机制/动态最可能产生它」，最后用原型验证动态是否真的出现。MDA 的价值是**沟通工具**，不是保证；动态很难预测，必须靠试玩。

## 4. 决策：玩法的核心货币

Sid Meier 的名言：游戏是「一系列有趣的决定」（a series of interesting decisions）。

**一个决定是否「有趣」**，通常取决于：

- **有取舍**：选了 A 就失去 B（机会成本）；
- **信息不完整**：有风险、有未知，但不是纯随机；
- **有后果**：结果会影响后续；
- **频率适中**：太密集会疲劳，太稀疏会无聊；
- **可理解**：玩家能预期大致结果，而不是开盲盒。

**常见决策类型**：

| 类型 | 例子 | 设计要点 |
| --- | --- | --- |
| 资源分配 | 把有限资源投给哪个属性 | 让每个选项都有明确的机会成本 |
| 风险/回报 | 深入高风险区域还是撤退 | 风险要可评估，不能纯赌 |
| 路线/顺序 | 先打哪个 Boss、先探索哪边 | 不同顺序产生不同故事与难度 |
| 构筑（build） | 技能/装备组合 | 组合之间有协同与反制 |
| 时机 | 何时进攻、何时防守 | 反馈要清晰，容错要合理 |
| 表达 | 对话态度、阵营、外观 | 不一定影响数值，但要让玩家感到被看见 |

**反模式**：主导策略（dominant strategy）、伪选择（选项等价）、无信息赌博、选择后果不可见。

## 5. 系统与涌现

- **正交机制（orthogonal mechanics）**：机制之间不重叠，组合时产生新玩法。例如「火会点燃草、草会燃烧、风会扩散火、水会灭火」——单个规则简单，组合复杂。
- **涌现（emergence）**：玩家用系统组合出设计师没写过的解法。*The Legend of Zelda: Breath of the Wild* 的化学引擎是典型：温度、火、电、金属、风互相作用，玩家可以「用金属武器引雷」「用火焰上升气流滑翔」。
- **系统叙事的代价**：可读性下降、Bug 面扩大、平衡困难、内容团队难以控制节奏。系统越强，越需要清晰的反馈与边界。
- **判断是否值得做系统**：它是否产生**新的决定**？如果只是让同一个决定更花哨，可能不值得。

## 6. 进度、难度与节奏

- **进度类型**：数值成长（等级/装备）、能力解锁（二段跳/抓钩）、地图开放（新区域）、知识成长（玩家理解）、社交成长（关系/声望）。
- **能力门槛（ability gating）**：用新能力打开旧空间（类银河恶魔城），让「回头」变成新内容。
- **难度曲线**：不是单调上升，而是「学习—练习—掌握—新挑战」的循环；允许玩家在某个区间停留。
- **张力曲线**：高强度战斗/解谜之后安排低强度探索/叙事；持续高压会让玩家麻木。
- **「30 秒的乐趣」**：Halo 的设计经验常被概括为——找到一个可以重复 30 秒仍然有趣的战斗循环，再围绕它做关卡。核心循环必须先在小尺度上成立。
- **节奏图**：把一章/一关画成「紧张—放松」的波形，检查是否有长段平坦或连续尖峰。

## 7. 奖励与经济

- **内在奖励**：掌握、好奇、表达、社交——更持久，但难设计。
- **外在奖励**：货币、装备、经验、解锁——有效，但可能挤出内在动机（过度奖励效应，overjustification effect）。
- **奖励节奏**：固定比率、可变比率、保底（pity timer）。可变比率容易让人上瘾，但也容易让人疲惫；保底提升公平感，降低挫败。
- **经济系统**：每个货币都要有**来源（source）**与**消耗（sink）**；没有消耗的货币会通胀，没有来源的目标会变成空头支票。
- **奖励与体验目标对齐**：如果游戏想表达「探索的乐趣」，就不要让探索的奖励只有数值；如果游戏想表达「战斗的紧张」，就不要用刷怪奖励稀释它。

## 8. 局内结构：Roguelike、开放世界与提取循环

**Roguelike / 局内循环**：

- 单局：进入 → 构筑 → 战斗 → 死亡/通关 → 带回资源；
- 元循环：解锁角色/卡牌/关系/剧情；
- 关键设计：随机性要「可学习」（玩家能逐渐理解概率与组合），死亡要有意义（带回知识/资源/叙事）。
- *Hades*：把死亡写成剧情推进，把「重复」变成角色关系与对话的载体。

**开放世界循环**：

```
探索 → 发现地标 → 遭遇/谜题/战斗 → 奖励/信息 → 获得新视角 → 更远的探索
```

- 地标要「远看可辨识、近看有内容」；
- 兴趣点之间要有「呼吸空间」，不是密度越高越好；
- 用系统性事件（天气、巡逻、随机遭遇）打破脚本化的可预测性；
- 避免「清单式开放世界」：如果所有兴趣点都是同一种图标，探索会退化为打卡。

**提取/风险循环**（extraction）：

- 进入高风险区域 → 获取资源 → 决定何时撤退 → 成功带出或全部失去；
- 核心张力来自「贪婪 vs 安全」，需要清晰的风险信息与可控的撤退手段。

## 9. 创新：新动词、新关系、新约束

玩法创新通常不是「发明一个全新品类」，而是改变以下一项或几项：

| 路径 | 含义 | 例子 |
| --- | --- | --- |
| 新动词 | 给玩家一个以前没有的动作 | *Portal* 的传送门；*Braid* 的时间倒流 |
| 新关系 | 改变玩家与系统/他人的关系 | *It Takes Two* 强制双人合作；*Death Stranding* 的异步连接 |
| 新约束 | 用限制制造新决策 | *Death Stranding* 的负重与平衡；*FTL* 的舱室氧气 |
| 新结构 | 改变进度/循环的组织方式 | *Outer Wilds* 的知识进度；*Hades* 的死亡循环 |
| 新叙事机制 | 让故事主题变成规则 | *Undertale* 的宽恕；*Spec Ops* 的暴力责任 |
| 新体验目标 | 追求不同的情绪 | *Journey* 的敬畏与陪伴；*Inside* 的压迫感 |

**判断创新是否成立**：

1. 它是否产生**新的决定**，而不只是新内容？
2. 玩家能否在 5 分钟内理解它？（可读性）
3. 它是否有**深度**（可组合、可精通）？
4. 它是否服务体验目标与设计支柱？
5. 它的**成本与风险**是否可控（技术、内容、平衡、教学）？

## 10. 指标与陷阱

- **留存/时长是代理指标，不是目标**：它们能说明问题，但不能定义「好玩」。用它们发现问题，不要用它们替代体验判断。
- **参与度伦理**：可变奖励、每日任务、限时活动可以提升留存，也可能变成操纵。问一句：玩家离开后会觉得「值得」还是「被消耗」？
- **循环没有意义**：刷素材、清图标、重复跑图——如果循环不产生新决定、新故事、新理解，它只是时间填充。
- **奖励通胀**：数值越给越大，玩家却越来越不兴奋；检查奖励是否还能被感知。
- **难度尖刺**：突然的难度跃迁通常不是挑战，而是反馈/教学不足。
- **功能蔓延**：每加一个系统，就多一份教学、UI、平衡、Bug 成本；先做减法。

## 12. 讨论检查清单

- [ ] 30 秒内能说清「玩家反复做什么、为什么」吗？
- [ ] 微/中/宏三个尺度是否都有设计，而不是只设计了一个？
- [ ] 核心循环里，玩家做的**决定**是什么？有几个？是否有取舍？
- [ ] 系统回应是否清晰、即时、可读？
- [ ] 循环是否有「弧线」提供终点与意义？
- [ ] 进度类型是什么？玩家在哪个维度上变强？
- [ ] 奖励是否服务体验目标？有没有挤出内在动机？
- [ ] 难度曲线是否有学习—练习—掌握的节奏？
- [ ] 随机性是否可学习？失败是否可归因？
- [ ] 创新点是否产生新决定，而不只是新内容？
- [ ] 如果删掉一个系统，体验会变差吗？如果不会，为什么要保留它？
