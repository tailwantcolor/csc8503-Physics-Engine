## 1. 设计结论

RE Engine 的“受击程序化抖动”不是单一模块，而是**动画采样之后的四层后处理**，每层都有独立参数资产，按“快→慢”叠加：

| 层 | 资产 | 时间尺度（推断） | 作用 |
| --- | --- | --- | --- |
| ① 冲击吸收 | `EmShockAbsorberState` + `*_shockabsorberparameter` | 0–80 ms | 身体/四肢的角弹簧+限位，受击瞬间被打偏再回弹 |
| ② 弯曲滤波 | `*_bend{walk,dash,fly}.user` | 40–300 ms | 脊柱/尾/翼的弯曲目标做一阶滤波与限位，产生滞后回弹 |
| ③ 物理链 | `*.chain2` | 80–600 ms | 尾/毛/布/绳的 verlet 链，受冲量后持续摆动 |
| ④ 顿帧/相机 | `playerhitstopparam`、`*_csk` | 0–200 ms | 顿帧 + 屏幕抖动，放大冲击观感 |

核心设计思想（**推断**）：**抖动不是“给骨骼加噪声”，而是“给目标姿态加一个带阻尼的二阶响应”**——冲击给一个速度/偏移，弹簧-阻尼把它拉回原位并允许过冲；限位保证不穿模；物理链负责长链结构。

## 3. 逐层拆解

### 3.1 冲击吸收：角弹簧 + 限位（Shock Absorber）

**设计（推断）**：每个受控关节/轴维护一个“偏移量” `x` 与速度 `v`，受冲击时注入冲量，之后按弹簧-阻尼回到 0：

```
on_impact(axis, impulse):
    v += impulse / mass
each_frame(dt):
    a = -k * x - c * v          # k 来自“速度/速率”，c 来自“阻尼”
    v += a * dt
    x += v * dt
    x = clamp(x, min_angle, max_angle)
    apply_to_joint(axis, x)     # 叠加在动画采样结果之后
```

- `min_angle/max_angle`（-90/180、-70/140、-30/120）保证回弹不会把关节甩穿。
- `damping` 0.1–0.3 决定来回几次；`rate` 0.9–4.0 决定快慢——数值越大越“弹”。
- 状态 `ALWAYS/DEFAULT/DEAD/EM0157_VEILOFF` 控制系统在死亡/特殊形态时关闭。

**为什么看起来像“抖动”**：受击冲量方向可能连续变化（多段命中、连击），每段都叠加一次速度，弹簧系统把这些冲量积分成多次过冲 → 高频抖动。

### 3.2 弯曲滤波：带限幅的一阶跟随（Bend Filter）

**设计（推断）**：

```
target = bend_from_animation()          # 动画/程序化目标弯曲
filtered += (target - filtered) * weight * (1 - exp(-dt / tau))
filtered = clamp(filtered, -max_angle, max_angle)
apply_bend(spine/tail/wing, filtered)
```

- 每组 `weight`（0.2/0.25/1.0）决定跟随强度；
- `max_angle`（5°/10°/30°/50°）是限幅；
- 三套文件按步态（walk/dash/fly）切换，因为不同步态允许的弯曲量不同。

受击时动画目标瞬间变化，滤波输出滞后 → 形成“甩动-回弹”的二次运动。

### 3.3 物理链：冲量驱动的 verlet 链（Chain2）

**设计（推断）**：

```
for each link i:
    v[i] += gravity * dt
    v[i] += (rest[i] - p[i]) * stiffness * dt
    v[i] *= (1 - damping)
    p[i] += v[i] * dt
    p[i] = collide(p[i], Character_Chain.cfil)
    constrain_distance(p[i-1], p[i], length[i])
```

- 重力 -9.8、刚度 0.25、阻尼 0.05（抽样值）；
- 碰撞过滤是角色专用（`Character_Chain.cfil`），避免穿身体/穿地；
- 受击时给链根一个冲量（推断来自受击事件/动作），尾部延迟摆动。

### 3.4 顿帧与相机：时间与画面层

- **Hitstop**：按攻击类型查表（`PlayerHitStopType`）冻结/减速若干帧；骨骼停在受击瞬间，视觉上“定住”，紧接着恢复时弹簧/物理链仍在运动 → 抖动被放大。
- **Camera shake**：`*_csk` 提供振幅/频率/衰减曲线；与骨骼无关，但让玩家把屏幕抖动归因到角色身上。

## 4. 合成时序（推断）

```

t=0..3f  hitstop（攻击类型决定），骨骼定格
```

各层参数独立：同一只怪的不同部位可以用不同阻尼/限位（10 组参数），所以“头甩得厉害、躯干稳”这种差异是**调参**出来的，不是换动作。

## 6. UE5 落地建议

1. **冲击吸收**：Control Rig 里对每个受控骨骼做“弹簧-阻尼 + 角度限位”，受击时注入角速度；或 AnimDynamics 的 Angular Spring。
2. **弯曲滤波**：用 Curve 驱动 + `FMath::FInterpTo`/弹簧节点做一阶跟随，再 Clamp 角度；按步态切换参数（walk/dash/fly 三套 DataAsset）。
3. **物理链**：Chaos Physics Asset / AnimDynamics 链，设重力、刚度、阻尼、碰撞通道（对应 `cfil`）；尾/毛/布各一条链。
4. **顿帧**：全局 Time Dilation 或动画采样暂停 1–5 帧；与受击类型表对应。
5. **相机抖动**：`UCameraShakeBase` 子类 + 每武器参数资产。
6. **合成顺序**：动画采样 → 冲击吸收 → 弯曲滤波 → 物理链 → IK 接地；物理链最后，避免被弹簧修正拉扯。
